# B-01 — Семантика зафиксирована до кода

Ни строки реализации ещё нет, и это единственный момент, когда обещания можно выбрать, а не
унаследовать. Три из них в стеке уже нарушались тихо: `petich-scheduler` допускает двойной запуск
и говорит об этом комментарием внутри `catch`, а не типом; petich теряет outbox-события на
не-outbox-хранилище, и это стало видно только когда завели счётчик. Обещание, живущее в
комментарии, не выполняется — оно просто не проверяется.

- **Решение: список обещаний и антиобещаний — файл в репозитории, а не раздел README.** README
  пересказывает, а список читает приёмка: каждый пункт либо имеет сценарий в
  `docs/features/`, либо помечен «проверяется человеком». Причина — из
  [research §1.1](../research/research-architecture.md): три центральных решения соседнего модуля
  противоположны нашим, и различить их можно только выписанными.
- Отвергнуто: «напишем в README при первом релизе». К релизу обещания уже вкомпилированы в API, и
  README описывает то, что получилось, а не то, что решили.
- Не покрывает: формат payload и выбор сериализации — это B-03.

- AC: в `docs/features/feature-durable-timer.md` есть раздел «Чего chronik не делает» из не менее
  чем пяти пунктов, каждый со ссылкой на решение D1–D8 ресёрча; при этом ни одно обещание не
  сформулировано словами «обычно», «как правило» или «старается».
- AC: единица времени названа в типе публичного API, а не только в тексте (D5).
- Anchors: `docs/features/feature-durable-timer.md`, `docs/research/research-architecture.md`,
  `chronik-core/src/commonMain/kotlin/EpochSeconds.kt`

## Закрыт 04.09.2026

Единица времени живёт в `EpochSeconds` — `value class` над `Long`, и другого способа назвать срок
у публичного API нет. Это ловит подстановку миллисекунд, которую `Long` принять обязан: срок в
56000 году не замечают, пока таймер не срабатывает.

Нормативная таблица отказов — семь строк, каждая со ссылкой на решение. **Одна ссылалась в
пустоту** и это нашлось только при сверке с приёмкой: «не повторяет бизнес-логику» было записано в
фичах и бэклоге, но номера решения не имело. Заведено как D9 — с причиной и с ценой (приложение
обязано не бросать из приёмника, когда упала его бизнес-логика).

Сверх плана: `TimerBoundaryTest` на шесть проверок вокруг `dueAt <= now` и истечения аренды.
Положительный контроль прогнан по-настоящему — подмена `<=` на `<` роняет `claimable in its own
due second`, — потому что зелёный тест границы без него ничего не утверждает.
