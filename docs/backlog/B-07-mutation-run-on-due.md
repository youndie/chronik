# B-07 — Мутационный прогон по границе времени

`due_at <= now` против `<`, секунда против миллисекунды, истёкшая аренда против ещё живой. Тест,
проверяющий свой же ответ, проходит при любом из этих вариантов, и именно здесь живут все
off-by-one.

- **Решение: мутации гоняются по двум выборкам прицельно, а не по проекту целиком.** Прогон по
  всему коду даёт список, который никто не разбирает; прогон по двум функциям даёт вердикт.
  Выживший мутант в границе времени означает, что граница не проверена, — это не «тест слабоват
  вообще».
- Оговорка, за которую уже заплачено в стеке: вердикт по одному мутанту — гипотеза, а не
  доказательство; выживший мутант иногда указывает не на тот рычаг. Разбор — по каждому выжившему
  отдельно, с записью «почему он выжил», а не сводным процентом.
- Не покрывает: крах и перераспределение — это [B-08](B-08-kill-harness.md).

- AC: по обеим выборкам ноль выживших мутантов, либо на каждого выжившего есть выписанная причина,
  почему он не ловится и что ловит вместо него.
- Anchors: `chronik-postgres/src/main/kotlin/`, `chronik-core/src/commonTest/kotlin/`
