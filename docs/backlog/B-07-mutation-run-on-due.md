# B-07 — Мутационный прогон по границе времени

`due_at <= now` против `<`, секунда против миллисекунды, истёкшая аренда против ещё живой. Тест,
проверяющий свой же ответ, проходит при любом из этих вариантов, и именно здесь живут все
off-by-one.

- **Решение: мутации гоняются по двум выборкам прицельно, а не по проекту целиком.** Прогон по
  всему коду даёт список, который никто не разбирает; прогон по двум функциям даёт вердикт.
  Выживший мутант в границе времени означает, что граница не проверена, — это не «тест слабоват
  вообще».
- Оговорка, за которую уже заплачено в стеке: вердикт по одному мутанту — гипотеза, а не
  доказательство; выживший мутант иногда указывает не на тот рычаг. Разбор — по каждому выжившему
  отдельно, с записью «почему он выжил», а не сводным процентом.
- Не покрывает: крах и перераспределение — это [B-08](B-08-kill-harness.md).

- AC: по обеим выборкам ноль выживших мутантов, либо на каждого выжившего есть выписанная причина,
  почему он не ловится и что ловит вместо него.
- Anchors: `dev/mutants.py`, `chronik-core/src/commonMain/kotlin/Timer.kt`,
  `chronik-postgres/src/main/kotlin/ExposedTimerStore.kt`

## Закрыт 04.09.2026

`dev/mutants.py` — одиннадцать мутантов по двум местам, где живёт граница времени:
`Timer.isClaimableAt` и запрос захвата в SQL. Все одиннадцать убиты, **каждый тем тестом, который
для него написан**.

**Второе утверждение важнее первого, и оно и есть содержание пункта.** Мутант, убитый не тем
тестом, — это не хорошая новость: значит проверка, написанная под это поведение, его не покрывает, а
спотыкается о него что-то постороннее. В день, когда постороннее поменяется по своим причинам,
поведение останется без сторожа и никто об этом не узнает.

**Три способа, которыми прогон отказывается пройти вхолостую:**

* базовый прогон делается первым, и красная база прерывает работу. На сломанной сборке убитыми
  выглядят все мутанты, и отчёт покажет идеальное покрытие пустоты;
* мутация, чей текст поиска в файле больше не встречается, — **ошибка, а не пропуск**. Список
  привязан к исходному тексту и протухает при рефакторинге; молчаливый пропуск превратил бы весь
  файл в украшение, сообщающее об успехе;
* файл восстанавливается из копии, снятой до прогона.

**Две находки в самом прогонщике, и обе нашлись проверкой прогонщика, а не кода.**

Первая: атрибуция читала **чужие протухшие XML**. Ядровому мутанту приписывалось убийство
`ExposedTimerStoreTest` — теста, которого задача `:chronik-core:jvmTest` не запускает вовсе.
Выживание судится по коду выхода и потому было верным всегда; неверной была атрибуция, а она —
половина утверждения. Результаты модуля теперь удаляются перед прогоном и читаются только его
собственные.

Вторая всплыла сразу после первой: мутант «захват игнорирует аренду» **не компилировался**. По коду
выхода это убийство, по существу — ничто: отвергнутый компилятором мутант не исполняет ни одного
теста. Заведён отдельный вердикт `NO COMPILE`, мутант переписан так, чтобы собираться. До
исправления атрибуции это прятал протухший XML.

Прогон не в `make check`: он гоняет набор по разу на мутанта, то есть минуты. В CI — по расписанию,
и **блокирующий**, в отличие от якорей: выживший мутант это утверждение об этом репозитории, и
чужой рефакторинг его вызвать не может.
