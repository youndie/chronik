# docs — chronik

chronik — долговечный таймер: `schedule(id, at, payload)`, и в момент `at` наружу уходит факт
«пора». Документация слоистая, ссылки идут сверху вниз.

```
[ Ресёрч (почему архитектура такая) ]
                 │
[ Фича (поведение + BDD) ] ──▶ [ Сервис / модуль (что чем владеет) ]
```

| Слой | Каталог | На что отвечает | Источник истины |
|---|---|---|---|
| Ресёрч | `research/` | *почему* так построено; что проверено, что гипотеза | артефакты, названные в каждом факте |
| Фича | `features/` | *что* система делает и *почему*; BDD-сценарии | этот репозиторий |
| Сервис | `services/` | модули: чем владеет, как собирается, как подключается | этот репозиторий |

Слоёв `screens/` и `api/` здесь нет, и это ответ, а не пробел: chronik — библиотека, у неё нет
клиента и в v1 нет HTTP-поверхности. Серверный режим заводится, когда появится потребитель не на
JVM (см. решение D2 ресёрча), и вместе с ним появится `api/`.

**Бэклог** — [backlog.md](../backlog.md): индекс и решения; сами пункты — по файлу в
[`backlog/`](backlog/), ссылка вида `[B-05](backlog/B-05-postgres-backend.md)`.

## Состояние: репозиторий пуст, и слои отражают это честно

Кода ещё нет. На `main` лежит только то, что можно проверить сегодня: ресёрч (его факты прочитаны
в чужих артефактах и исходниках) и бэклог. Слои `features/` и `services/` описывают то, чего пока
не существует, поэтому живут в открытой ветке `docs/v1-specification` со `status: draft` и
приезжают на `main` по мере того, как приезжает код.

Это не формальность: документ со `status: draft` на `main` означает, что намерение записано как
факт, и проверка `docs_check.py --on-main` считает это дефектом.

## Соглашения

- **`id`** во фронтматтере уникален и равен имени файла.
- Межслойные ссылки — id во фронтматтере **и** обычные markdown-ссылки в теле.
- Один документ — одна сущность.
- BDD-сценарии пишутся по коду, а не по памяти. Пока кода нет, сценарий помечен как *целевой*, и
  при его реализации сверяется с настоящим поведением — до слияния, а не после.
- **Заголовок сценария — `### Scenario: <русский текст>`, ключевое слово английское.** Его читают
  две проверки (`docs_check.py` и `bdd_report.py`), и обе ищут именно это слово. Русское
  «Сценарий» не ломает ничего видимого — сценарии просто перестают считаться, и отчёт показывает
  ноль там, где их двадцать три. Автоматизированный сценарий несёт строку `**Automated:** <тест>`;
  отсутствие строки означает, что проверка ручная, и эта асимметрия — то, ради чего отчёт есть.
- **В строке `**Automated:**` пишется только имя теста, без модуля.** Формат разрешает два токена,
  и первый из них означает **репозиторий**. `chronik-core OracleTest` читается как «репозиторий
  chronik-core», такого каталога рядом нет — и проверка существования теста **молча выключается**:
  отчёт засчитывает строку и ничего не говорит. Проверено намеренно сломанной ссылкой
  (`NoSuchTestAnywhere` засчитался как автоматизированный); с одним токеном та же подделка
  отчётом ловится. Модуль, если он нужен читателю, называется в тексте сценария.
- **Проверять ссылку надо после коммита.** `bdd_report.py` ищет через `git grep`, то есть видит
  только отслеживаемые файлы: только что написанный тест числится отсутствующим, пока не
  закоммичен, и это не дефект ссылки.
- **Главный читатель — кодовый агент.** В каждом документе есть пути в код, чтобы читатель попадал
  туда за один шаг. Не дублировать то, что живёт в коде (поля DTO, ключи конфигурации) — давать
  путь: копия протухает, путь нет.
- **Язык.** Документация — русская, код английский: комментарии, KDoc, имена тестов, сообщения
  исключений, сообщения коммитов и корневой `README.md`. Идентификаторы, координаты артефактов и
  имена классов — дословно как в коде. Якоря решений пишутся латиницей (`D3`), потому что на них
  ссылаются из английских комментариев.

## Проверки

```bash
make check
```

То же самое врозь:

```bash
pip install pyyaml
python3 scripts/backlog_index.py --check
python3 scripts/docs_check.py
python3 scripts/coverage_map.py --check
python3 scripts/bdd_report.py
python3 scripts/code_anchors.py --repos ..
```

только состав.

  проектах, восемь решений, риски и три отклонения от исходного брифа

### Services (4)

Модули chronik:

- [x] [chronik-core](services/chronik-core.md) — примитив: три операции, контракты хранилища и
  приёмника, воркер; SQL не знает
- [x] [chronik-postgres](services/chronik-postgres.md) — единственный модуль, знающий SQL: выборка
  `SKIP LOCKED`, аренда колонкой, таблица без DDL
- [x] [chronik-conformance](services/chronik-conformance.md) — корпус случаев, гоняемый против
  любой реализации хранилища

Мост, живущий в чужом репозитории:

- [x] [petich-chronik](services/petich-chronik.md) — шаг `awaitUntil`, срок на шаге, отмена как
  компенсация; заводится в petich после решения судьбы `petich-scheduler`
